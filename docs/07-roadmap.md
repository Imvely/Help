# 07. 로드맵과 리스크

## 1. 마일스톤

| 단계 | 기간(1인 기준) | 산출물 | 완료 기준 |
|---|---|---|---|
| **M0 데이터 파이프라인** | 3~4주 | docker-compose, Postgres 스키마, C002/I0490/영양DB 전체 덤프 + 정규화, 성분 KB 시드 200종, 알레르겐 온톨로지 | 국내 가공식품 20만+ SKU 적재, 원재료 매칭률 80%, KB 등급 전부 출처 보유 |
| **M1 바코드 MVP** | 4~5주 | Expo 앱(스캔·카드·상세·검색·히스토리), FastAPI `/products/*`, 로컬 캐시 | 실기기 바코드→카드 p50 < 150ms, 바코드 매칭률 60%+, TestFlight/내부테스트 배포 |
| **M2 OCR + 기여** | 3~4주 | 라벨 촬영 화면, PaddleOCR 워커, Claude 구조화, 확인·수정 UI, 정정요청 | 골든셋 100장 원재료 파싱 F1 ≥ 0.85, 원산지 라인 추출 ≥ 0.9 |
| **M3 로그인·개인화·푸시** | 3주 | Supabase Auth 4종, 프로필(로컬+opt-in 동기화), 기기 내 판정, 회수 푸시 | Apple 심사 통과, 민감정보 별도 동의 플로우, 회수 매칭→푸시 1시간 내 |
| **M4 이미지 인식** | 5~6주 | 바코드 세션 프레임 기여, 갤러리 ≥ 5천 SKU, DINOv3 파인튜닝, `/recognize`, 시간적 투표 | top-1 ≥ 85%(확정 임계), 비전 경로 p50 < 400ms, 피처 플래그로 점진 활성 |
| **M5 성장 기능** | 지속 | 대체 제품 추천, 비교, 가족 프로필, 영양 A~E, 화장품 전성분 OCR, 온디바이스 임베딩 | KPI([02-product-spec.md](02-product-spec.md) §8) 달성 |

MVP 출시 = M1+M2+M3 (약 3개월). M4는 데이터가 쌓이는 동안 병렬로 모델 준비.

## 2. 스캐폴드 현황 (2026-10-14 완료)

```
apps/mobile/      Expo SDK 57 + VisionCamera 4.7 바코드 스캐너, 결과 카드, 상세/기록/프로필/검색/정정 화면, SQLite 캐시
apps/api/         FastAPI + SQLAlchemy 2 + Alembic, 전체 스키마(docs/04), products/recalls/kb/contributions/recognize/ocr
                  라우터, 원재료 파서, 알레르겐 매칭, 원산지 문구, KB 시드(성분 33·알레르겐 33), 식약처 파이프라인 CLI
                  (app/pipeline/mfds_sync.py: dump/normalize/recalls), pytest 36개
packages/domain/  개인화 엔진(알레르기·카페인·임신·당뇨·고혈압·신장·비건·어린이·등급), vitest 65개
docker-compose.yml  postgres(pgvector)·redis·minio·api·worker
.github/workflows/ci.yml  pytest+ruff / vitest+tsc / tsc
```

M0 잔여: 실제 식약처 인증키로 C002 전체 덤프 실행, 정규화 매칭률 측정, 수입식품정보마루 제공신청.
M1 잔여: 실기기 빌드(EAS dev build), 앱 도메인 어댑터를 `@eodisan/domain` 실제 패키지로 교체, 레이턴시 측정.

## 3. 리스크 레지스터

| # | 리스크 | 영향 | 가능성 | 대응 |
|---|---|---|---|---|
| R1 | **원재료 원산지 데이터 공백**(공공 API에 없음) | 핵심 기능(a) 커버리지 낮음 | 높음 | M2 OCR 폴백을 MVP에 포함, 크라우드소싱 검증(3인 일치), 코리안넷 제휴 협의 조기 착수 |
| R2 | **신제품 바코드 매핑 불가**(C005 2018 중단) | 편의점 신상 미인식 | 높음 | OCR로 제품명→C002 매칭, 사용자 제보로 바코드 등록, 코리안넷 제휴 |
| R3 | 수입식품정보마루 API 부재 | 제조국 데이터 지연 | 중 | 공공데이터 제공신청(처리 수 주), SDFI 제휴 병행, 그동안 라벨 OCR |
| R4 | 화장품 전성분 DB 부재 + EWG 사용 불가 | 화장품 기능 지연 | 높음 | 화장품은 M5로, KCIA 협의, 성분 KB는 CosIng·식약처 고시 기반 |
| R5 | 명예훼손·업무방해 분쟁(특정 제품 부정 표시) | 법적·브랜드 | 중 | 출처 귀속 표현, 사실/의견 분리, 정정 채널 72h, 면책 문구([08-legal-privacy.md](08-legal-privacy.md)) |
| R6 | 민감정보 유출 | 법적(PIPA) | 낮음 | 기본 기기 저장, 서버는 암호화 payload, 로그 마스킹, 별도 동의 |
| R7 | 이미지 인식 정확도 미달 | P1 기능 지연 | 중 | 바코드 플라이휠로 데이터 확보 후 활성, 확정 임계 미만은 후보 UI |
| R8 | VisionCamera v5/Nitro 생태계 변동 | 빌드 깨짐 | 중 | 버전 고정(lockfile), dev build, 업그레이드는 분기 1회 |
| R9 | 식약처 API 호출 제한·장애 | 데이터 갱신 지연 | 중 | raw 테이블 보존, 일배치 재시도, 증분 7일 창 활용 |
| R10 | Apple 심사(4.8 로그인, 건강정보) | 출시 지연 | 중 | Sign in with Apple 동등 노출, 건강 데이터 사용 목적 명시, 의료 조언 아님 고지 |
| R11 | 특정 국가 표시가 혐오·불매 프레임으로 소비됨 | 브랜드·법적 | 중 | 국가별 색상 차등 금지, 가치 판단 문구 금지, "원산지 ≠ 안전" 고정 문구 |

## 4. 열린 질문(사용자 결정 필요)

1. 화장품을 MVP에 넣을지(데이터 공백 때문에 M5로 미룸을 제안) 또는 라벨 OCR만으로라도 넣을지.
2. 코리안넷·KCIA 제휴 협의를 누가 언제 시작할지(사업자 등록 필요 가능성).
3. 수익 모델(프리미엄 vs 커머스 제휴). 커머스 제휴는 표시광고법 리스크를 키움.
4. 앱 이름 "어디산" 상표 검색 결과에 따른 최종 확정.
