# 02. 기획 — 기능 명세

## 1. 핵심 사용자 흐름(Happy path)

```
앱 실행 → 카메라 화면(기본 탭)
  → 제품을 비춤 (셔터 없음)
  → 0.1~0.4초 내 하단에 "결과 카드" 슬라이드 업
      [제품명 · 브랜드]
      [원산지 배지 3단: 제조국 / 원재료 원산지 / 브랜드 국가]
      [성분 등급 요약: 안전 n · 주의 n · 논쟁 n · 유해 n]
      [알레르기 · 카페인 · 대체당 칩]
      [내 프로필 경고 (로그인 시)]
      [출처: 식약처 C002 / 라벨 OCR / 사용자 제보]
  → 카드 탭 → 상세 화면(성분 하나하나 설명, 근거, 대체 제품)
```

핵심 원칙 세 가지:
1. **셔터 없음.** 비추면 뜬다(Vivino 방식). 셔터를 누르는 순간 "빠르다"는 인상이 사라진다.
2. **결과는 카드 한 장에.** 스크롤 없이 가장 중요한 세 가지(원산지·등급·내 경고)가 보여야 한다.
3. **모든 정보에 출처.** 어떤 숫자든 "어디서 왔는지"를 한 줄로 단다.

## 2. 기능 목록과 우선순위

우선순위 기준: **사용자 가치 × 데이터 확보 가능성 × 구현 비용**. 리서치([01-research.md](01-research.md))에서 공공데이터로 바로 되는 것은 앞으로, 제휴·크라우드소싱이 필요한 것은 뒤로 뒀습니다.

## 3. 화면 구성

| 화면 | 역할 | 핵심 요소 |
|---|---|---|
| **스캔(홈)** | 앱의 기본 화면 | 전체 화면 카메라, 중앙 가이드 박스, 하단 결과 카드, 우상단 플래시/검색/프로필 |
| 결과 카드(바텀시트) | 3초 요약 | §4 참고. 드래그로 상세 전환 |
| 제품 상세 | 전체 정보 | 탭: 원산지 / 성분 / 영양 / 내 프로필 / 대체 제품 / 출처·정정 |
| 성분 상세 | 성분 하나 교육 | 쉬운 설명 → 용도 → 규제 상태(KR/EU/US) → 근거 수준 → 참고 링크 |
| 라벨 촬영(OCR) | 폴백 | "원재료명 영역을 네모 안에" 가이드, 촬영 후 파싱 결과 확인·수정 |
| 검색 | 텍스트 검색 | 자동완성, 최근 검색 |
| 히스토리 | 스캔 기록 | 날짜별, 필터(식품/화장품/경고 있음), 비교 선택 |
| 프로필 | 건강 프로필·가족 | 알레르기 체크리스트, 민감도 슬라이더, 민감정보 별도 동의 |
| 설정 | 로그인·알림·데이터 | 동기화 opt-in, 데이터 삭제 |

## 4. 결과 카드 상세 설계

```
┌─────────────────────────────────────────┐
│ ⚠ 회수·판매중지 (있을 때만, 빨강 배너)      │
├─────────────────────────────────────────┤
│ [썸네일] 종가집 포기김치 1kg               │
│          대상㈜ · 김치류                   │
├─────────────────────────────────────────┤
│ ⚠ 내 프로필: 새우 포함 (젓갈) · 나트륨 높음  │  ← 로그인+프로필 있을 때
├─────────────────────────────────────────┤
│ 원산지                                   │
│  제조국 🇰🇷 한국   브랜드 🇰🇷 한국          │
│  원재료  배추 국산 · 고춧가루 🇨🇳 중국산 ·   │
│         마늘 국산 · 4순위 이하: 표시 의무 없음 │
├─────────────────────────────────────────┤
│ 성분  ● 안전 12  ● 주의 1  ● 논쟁 0  ● 유해 0 │
│  알레르기: 새우, 대두 ｜ 혼입 가능: 밀       │
├─────────────────────────────────────────┤
│ 출처: 식약처 품목제조보고(2025-03) · 라벨 OCR │
│ (2026-09, 3명 확인)  [정보가 틀려요]        │
└─────────────────────────────────────────┘
```

**원산지 배지 문구 규칙**(법적 방어의 핵심, [08-legal-privacy.md](08-legal-privacy.md)):
- 반드시 레벨을 붙인다: "제조국: 중국", "원재료 중 고춧가루: 중국산", "브랜드: 한국(OEM 제조국: 중국)".
- 표시 의무가 없는 원료(4순위 이하, 첨가물, 향료)는 **"알 수 없음"**. 절대 "중국산 아님"으로 추정하지 않는다.
- "원산지는 안전·품질을 뜻하지 않습니다" 문구를 상세 화면 원산지 탭 하단에 고정.
- 색상은 국가별로 다르게 쓰지 않는다(특정 국가 빨간색 금지). 국기 이모지 + 국가명만.

**성분 등급 색상**: 0 안전(초록) · 1 주의(노랑) · 2 논쟁(주황) · 3 유해(빨강) · 미확인(회색). 등급 옆에 항상 근거 수준 아이콘(규제결론 🏛 / 문헌 📚 / 관찰연구 🔬 / 동물·세포 🧪).

## 5. 개인화(건강 프로필) 차원

리서치([05-knowledge-base.md](05-knowledge-base.md) §5)의 가치 평가에 따라 MVP에 넣을 차원을 골랐습니다.

| 차원 | 입력 | 판정 데이터 | MVP |
|---|---|---|---|
| 식품 알레르기 | 19항목 체크 + 커스텀 텍스트(참깨·견과 세부) | 알레르기 표시 + 원재료명 | ✅ |
| 혼입 가능도 경고 | 토글("심한 알레르기") | "혼입 가능" 문구 | ✅ |
| 카페인 | 민감도(보통/민감/피함) + 임신 여부 → 한도 자동(400/300/체중×2.5) | 카페인 함량(OCR) | ✅ |
| 임신·수유 | 토글 | 식품: 카페인·주류·비살균 / 화장품: 레티노이드·고농도 살리실산·하이드로퀴논("전문가 권고" 라벨) | ✅ |
| 당뇨 | 토글 | 당류 g, 감미료 종류 | ✅ |
| 고혈압 | 토글 | 나트륨 mg, 1일 기준치 % | ✅ |
| 피부타입·고민 | 건성/지성/복합/민감 + 여드름/아토피 | 대한피부과의사회 가이드(근거 약함 명시) | ✅(화장품) |
| 어린이 | 가족 프로필 나이 | 타르색소, 카페인, 고열량·저영양 | P1 |
| 신장질환 | 토글 | 인산염 첨가물명(함량 데이터 없음 명시) | P1 |
| 비건·채식 | 토글 | 원재료 파싱 + 인증 | P1 |
| 글루텐프리 | 토글 | 밀·메밀 표시(보리·호밀 미표시 한계 명시) | P1 |
| 할랄·코셔 | 토글 | 돼지고기·주정 + 인증 로고 | P2 |
| 반려동물 | 모드 | 자일리톨·포도·초콜릿·양파 | P2 |

**설계 원칙**: 프로필은 **기본적으로 기기에만 저장**(SecureStore). 서버는 성분 목록을 내려주고 **판정은 기기에서** 한다 → 알레르기 정보가 서버로 가지 않아도 개인화가 동작한다. 동기화(기기 간 공유, 가족 프로필 공유)는 별도 동의 후 opt-in.

## 6. 비회원 vs 회원

| | 비회원 | 회원 |
|---|---|---|
| 스캔·결과 카드·상세·OCR·검색 | ✅ | ✅ |
| 히스토리 | 기기 50건 | 무제한, 기기 간 동기화 |
| 건강 프로필 | 1개(기기 로컬) | 가족 프로필 다수, 동기화 |
| 개인화 경고 | ✅(로컬 프로필 기준) | ✅ + 회수 푸시 |
| 즐겨찾기·비교·메모 | ❌ | ✅ |
| 제보·정정요청 | ✅(익명) | ✅(기여 이력, 신뢰도 가중) |
| 대체 제품 추천 | 기본 | 프로필 반영 |

비회원도 핵심 가치를 전부 누리게 하는 이유: 편의점에서 "일단 한번 비춰보는" 첫 경험이 전환의 전부이기 때문입니다. 로그인은 **저장·동기화·가족**이 필요해질 때 자연스럽게 권합니다.

## 7. 데이터 기여 루프(크라우드소싱)

공공데이터만으로는 원재료 원산지·신제품 바코드·화장품 전성분이 비어 있습니다([01-research.md](01-research.md) §2). 사용자가 쓰는 행위 자체가 데이터가 되도록 설계합니다.

1. **바코드 인식 성공 시** 같은 세션의 앞면 프레임(동의 하에, 저해상도)을 이미지 갤러리에 자동 등록 → 이미지 인식(P1-1)의 학습 데이터.
2. **정보 부족 시** "뒷면을 비춰주세요" → OCR 결과를 사용자가 확인/수정 → `source=ocr_user`로 저장. 같은 제품에 3명 이상 동일 값이면 `verified`.
3. **정정 요청**은 기업 계정과 일반 사용자 모두 가능. 처리 상태를 제보자에게 알림.
4. 기여 포인트(배지)는 P2.
